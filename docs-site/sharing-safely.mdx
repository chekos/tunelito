---
title: "Sharing safely"
description: "Understand Tunelito's review-key access model and tunnel exposure."
---

Tunelito is built for temporary collaboration, not permanent hosting.

## Review keys

Shared sessions include a generated `tunelito_key` in printed URLs by default:

```text
https://example.trycloudflare.com/?tunelito_key=...
```

The key is bearer access. Anyone with the full URL can view the page and leave comments.

The first valid request sets a short-lived HTTP-only cookie so page assets and WebSocket sync keep working.

Reviewer identity IDs are only used to support display-name renames. They are not authentication, authorization, or proof of who a reviewer is.

## Owner sessions

Tunelito assigns owner and visitor roles on the server. Direct loopback `Local:` sessions are treated as the owner; public tunnel or forwarded sessions are treated as visitors.

`--owner <name>` only seeds the editable display name for the local owner. It is not an account login or permission system. If the owner opens the `Public:` URL, that browser is treated as a visitor. Visitors cannot become owners by editing browser state or submitted comment fields.

## Local Markdown source editing

`--editable` is an explicit source-write capability for Markdown, but it does
not turn the review key or owner display name into edit authorization. Source
reads and saves additionally require a direct loopback request, a loopback Host,
no forwarding headers, and—for saves—a matching same-origin request plus the
source revision that was opened. Public tunnel URLs remain read-only even when
the session was started with `--editable`, and `--no-auth` does not broaden
source editing beyond the direct local URL.

Tunelito revalidates the file at save time, accepts only safely served `.md`
targets and bounded UTF-8 content, and writes through a same-directory atomic
replacement. A stale revision fails without changing the source.

## Public tunnels

When tunneling is enabled, Tunelito exposes your local server through Cloudflare Tunnel. Use this only for material you are comfortable sharing with anyone who has the full link.

## Ephemeral live sessions

`--ephemeral` keeps comments in memory only and does not write a comments file. It changes persistence, not exposure: the session is still served over the same tunnel and review key, so "nothing saved" is not "nothing exposed." The same bearer-link access model still applies: anyone with the full URL can view the page and participate while the local server is running. For a sensitive page, combine `--ephemeral` with `--no-tunnel`.

WebRTC data channels are encrypted by the browser when peer-to-peer connectivity is available. The WebSocket connection remains active for signaling, reloads, and fallback relay. Tunelito does not configure third-party STUN or TURN servers.

## Local agent worker

The agent worker is explicit opt-in. When `--agent` is enabled, reviewer comments become input to a local CLI that can edit files in the served folder. Use it for trusted review sessions, add `--agent-trigger "@agent"` so only marked comments are actionable, or combine owner identity with `--agent-policy owner-or-mention --agent-trigger "@agent"` for owner-led sessions. Direct local owner sessions can approve a specific visitor comment for agent work, but that approval still only matters when `--agent`, `--agent-command`, or `--agent-session` is explicitly enabled. Tunelito blocks the agent state file, temp file, and derived log file from static serving even if a custom `--agent-state` path is inside the served folder.

`--agent-session` has the same trust boundary but does not spawn a child process. The server process watches comments, claims actionable feedback for the current agent session, prints prompts with `tunelito inbox record --claim ...` commands, shows the current work on browser comment cards and through `tunelito inbox status`, and writes `.tunelito/session.json`. Reviewer comments still become instructions to the current local agent session, so use the same owner or mention policies for shared calls.

## Disable public tunnels

```bash
tunelito ./page.html --no-tunnel
```

## Disable review-key auth

```bash
tunelito ./page.html --no-auth
```

`--no-auth` only removes the review-key gate; it does **not** disable the tunnel. A tunneled session started with `--no-auth` is a public, unauthenticated URL that anyone who finds it can open and comment on. It cannot use the direct-local Markdown editor, but the document is still exposed. If you want no key, add `--no-tunnel` so the session stays local. Use `--no-auth` only for trusted local networks or throwaway demos.
