`tunelito --help` shows a one-screen summary. `tunelito help <topic>` prints one
section below (`agent`, `markdown`, `link-preview`, `network`, `json`), and
`tunelito <command> --help` prints a command's options. This page is
`tunelito help all`:

```text
Tunelito 0.27.1

Usage:
  tunelito <page.html|notes.md|folder> [options]

Core:
  --no-tunnel           Keep the room on this machine; no public link
  --open                Open the Local URL in your default browser
  --editable            Edit Markdown source from the Local URL (shared links stay read-only)
  --ephemeral           Keep comments in memory only; they are lost when Tunelito stops
  --comments <path>     Markdown comments file (default: <page-or-folder>.comments.md)
  --agent <codex|claude|custom>
                        Run a local coding-agent worker on new comments
  --agent-session       Let the current coding-agent conversation handle comments
  --json                Print startup and runtime events as JSON lines (for scripts and agents)
  --verbose             Also print theme, session metadata, and handoff rows at startup
  -v, --version         Show version
  -h, --help            Show this help

Network and access:
  --port <number>       First port to try; Tunelito moves up to the next free one (default: 4317)
  --host <host>         Host to bind locally (default: 127.0.0.1)
  --no-tunnel           Only serve the Local URL; do not start Cloudflare Tunnel
  --no-auth             Drop the review key; anyone with a link can view and comment

Markdown presentation:
  --theme <name>        Markdown theme: default|editorial|technical|bns-pitaya
  --markdown-css <href> Add a stylesheet link to rendered Markdown pages
  --no-code-wrap        Scroll long lines in Markdown code blocks instead of wrapping
                        them (--code-wrap restores the wrapping default)
  --editable            Let the direct local owner edit safely served Markdown
  --section-index       Show a sticky Markdown section index on wide viewports
  --owner <name>        Seed the editable owner name for the direct local viewer

Project defaults live in tunelito.config.json; run `tunelito config show <target>`
to see the resolved values and where each came from.

Link previews (Markdown):
  --link-preview <regex> <url-template>
                        Show a Markdown hover card for links matching regex, filled from
                        resolver JSON fetched by the Tunelito server (repeatable)
  --link-preview-fields <title=path,status=path,priority=path>
                        JSON paths for the preceding --link-preview rule
  --link-preview-header '<Name>: <value>'
                        Add a request header to the preceding --link-preview rule; read secrets
                        with ${env:NAME} (single-quote it; repeatable, owner-only)
  --link-preview-env <NAME>
                        Allow resolver headers to read this environment variable; required
                        for any resolver header, CLI only (repeatable)
  --link-preview-allow-remote
                        Allow https resolvers on non-loopback hosts (default: loopback only)
  --link-preview-visitors
                        Also resolve previews for keyed public visitors (default: owner only)

Agents:
  --agent-session       Watch comments for the current agent session; do not spawn a worker
  --agent <codex|claude|custom>
                        Run a local coding-agent worker for persistent comments
  --agent-command <cmd> Custom shell command for --agent custom; prompt is sent on stdin
  --agent-interval <s>  Agent fallback polling interval in seconds (default: 120)
  --agent-policy <mode> Which comments are actionable: all|mention|owner|owner-or-mention (default: all)
  --agent-trigger <txt> Marker for mention policies, or "all" (default: all)
  --agent-instructions <txt>
                        Append host instructions to the built-in agent prompt
  --agent-instructions-file <path>
                        Append host instructions from a file
  --agent-prompt <txt>  Replace the built-in agent behavior prompt
  --agent-prompt-file <path>
                        Replace the built-in agent behavior prompt from a file
  --agent-max-attempts <n>
                        Stop retrying a comment after n attempts (default: 2)
  --agent-max-passes <n>
                        Stop continuing a multi-pass comment after n agent passes (default: 3)
  --agent-state <path>  Agent resolution ledger (default: <target>/.tunelito/agent/state.json)

--agent-session and --agent both need persistent comments, so neither works
with --ephemeral. Run `tunelito skill show` for the full agent workflow.

JSON event stream (--json):
  stdout carries one JSON object per line instead of the human startup block.
  Every event has "type" and "time". Types, in order of appearance:
    started    version, target, localUrl, commentsPath, sessionPath, tunnel, auth,
               ephemeral, editable, theme, agent, commands (handoff, tracker, record)
    tunnel     state: starting|fallback|dns-wait|ready|unavailable|disabled,
               plus publicUrl (ready), hostname/code (dns-wait), error (unavailable)
    viewers    count
    comment    id, author, authorRole, scope, pagePath, body
    reload     a source file changed and browsers were asked to reload
    review     sequence, comments (a reviewer pressed Done Reviewing)
    agent      message (single-line agent worker or inbox note)
    prompt     text (multi-line agent-session claim prompt)
    warning    message (session metadata or browser-open problems)
    stopped    elapsedMs, newComments
  Errors still go to stderr as text, with exit code 2 for usage and 1 for runtime.

Commands:
  doctor                Check local setup and sharing safety (read-only)
  session status        Inspect or recover the last session for a target
  inbox                 Claim, track, and record comments for an active agent
  comments inspect      Print a structured index of a comments file
  review watch          Wait for a reviewer's Done Reviewing handoff
  config show           Print resolved Markdown settings and where they came from
  skill                 Print, explain, or install the Tunelito agent skill
  mcp                   Start a stdio MCP server for comments and inbox tools
```

## Errors and exit codes

Errors print the problem on one line and the fix on the next. They never print
the whole help:

```text
tunelito: Unknown option --no-tunel
Did you mean --no-tunnel?
Run `tunelito --help` for usage.
```

Usage errors (unknown or removed flags, missing targets) exit with `2`. Runtime
errors exit with `1`. Set `TUNELITO_DEBUG=1` to print the stack trace for an
unexpected failure.

Flags removed in 1.0 fail with their replacement: `--out` → `--comments`,
`--live` → `--ephemeral`, `--owner-name` → `--owner`.

## Scripting with --json

```bash
tunelito ./site --json | jq -r 'select(.type=="tunnel" and .state=="ready") | .publicUrl'
```

`inbox`, `doctor`, `session status`, `comments inspect`, `config show`, and
`review watch` also accept `--json` for a single machine-readable report.

## Common examples

Start a public review session:

```bash
tunelito ./page.html
```

Serve a Markdown memo with the built-in readable page style:

```bash
tunelito ./notes.md
```

Let only the direct local owner edit that Markdown source in the browser while
public or forwarded review links remain read-only:

```bash
tunelito ./notes.md --editable --open
```

The source editor saves only on an explicit action or Cmd/Ctrl-S. Every save
requires the revision that was opened, rechecks it immediately before commit,
and atomically replaces the file while preserving its permissions. If that
optimistic check observes an external editor or agent changed the source first,
Tunelito preserves the browser draft. Generated folder pages, HTML, hidden or blocked paths, symlink escapes,
comments/config/session state, and files larger than 2 MiB are not editable.

Choose a bundled Markdown theme:

```bash
tunelito ./notes.md --theme editorial
```

Persist themes and CSS with project or global configuration, then inspect the resolved layers:

```bash
tunelito config show ./notes.md
tunelito config show ./notes.md --json
```

See [Markdown themes and configuration](/configuration) for file locations, precedence, and the config schema.

Show tracker details on hover for bare links such as `[TLL-563](http://127.0.0.1:3100/TLL/issues/TLL-563)`:

```bash
tunelito ./briefing.md \
  --link-preview '^http://127\.0\.0\.1:3100/(?<team>[A-Z]+)/issues/(?<id>[A-Z]+-\d+)$' \
                 'http://127.0.0.1:3100/api/{team}/issues/{id}' \
  --link-preview-fields 'title=title,status=state.name,priority=priority.label'
```

The regex is matched against the link's `href` as written. `{0}` is the whole match, `{1}`–`{9}` are numbered groups, and `{name}` is a named group. Each value is URL-encoded before it goes into the template, and the scheme and host must be literal. The Tunelito server fetches the JSON, so the browser never contacts the resolver. Resolvers must be loopback hosts unless `--link-preview-allow-remote` is passed, and a remote resolver must use `https://`. Previews are served to the direct local owner only; `--link-preview-visitors` also serves keyed tunnel visitors. An authored link title always wins over resolved data. See [How it works](/how-it-works#resolver-backed-link-previews) for limits and the trust boundary.

A resolver that needs a token can send a header. The value reads the secret from an environment variable, and `--link-preview-env` names each variable Tunelito may read:

```bash
export TRACKER_TOKEN=...
tunelito ./briefing.md \
  --link-preview '^https://tracker\.example\.com/issues/(?<id>[A-Z]+-\d+)$' \
                 'https://tracker.example.com/api/issues/{id}' \
  --link-preview-header 'Authorization: Bearer ${env:TRACKER_TOKEN}' \
  --link-preview-env TRACKER_TOKEN \
  --link-preview-allow-remote
```

Single-quote the header so your shell does not expand `${env:…}`. Headers go only to that rule's resolver origin, over `https://` or loopback `http://`, and never on a redirect. Credential-looking headers (`Authorization`, `Cookie`, or a name containing `token`, `key`, `secret`, `auth`, or `session`) must be `${env:NAME}` or `<Scheme> ${env:NAME}`; a literal secret is refused. A rule with headers serves the direct local owner only, even with `--link-preview-visitors`. If the variable is unset or empty, that rule shows no card and Tunelito prints one warning that names the variable. Startup output, `config show`, and errors show `${env:NAME}`, never the value.

Fenced `mermaid` blocks render automatically from Tunelito's packaged same-origin runtime. Other fenced languages stay as source code, and invalid diagrams keep a readable source fallback. Each non-Mermaid code block shows a copy button on hover or keyboard focus; it copies the code exactly as written. Long code lines wrap by default, and a wrap toggle beside the copy button switches one block back to sideways scrolling. `--no-code-wrap` (or `"codeWrap": false` in config) makes scrolling the default.

Defined GFM footnotes such as `statement[^note]` render as numbered links with a footnotes section and return links. Definitions remain selectable for comments; undefined references and footnote syntax inside code remain literal.

Complete HTML comments are hidden from the rendered reader surface while literal comment syntax inside code stays visible. In folder mode, the collapsible left sidebar labels its injected served-document tree as `Tunelito navigation`; root documents stay visible and nested folders start closed. Leading YAML front matter renders below it as a separate source-derived Properties section, which is omitted when a note has no front matter. Folder URLs without an authored index receive a themed landing page with immediate documents, child folders, and safe parent navigation. Common Obsidian wiki references such as `[[Note]]`, `[[Note|Alias]]`, and heading variants render as unresolved inline references without inventing navigation targets. On desktop, a compact, vertically centered right-edge document-map dial marks the real rendered headings and content blocks; it expands while hovered or visibly keyboard-focused and retreats when the pointer leaves. h1 through h6 remain keyboard-navigable, while paragraph ticks show reading progress as you scroll. The map selects the first block at the top of the page and the last block at the bottom. Explicit `{#id}` anchors and the nearest heading keep comments attached across edits. `{todo}` and `{high}` tokens render as pills outside code, H2 and H3 sections fold in the browser, and `--section-index` adds a sticky section list on wide screens. Titled links show a local hover card in place of the native `title` tooltip, which returns when the card closes. Links to another origin open in a new tab with `rel="noopener noreferrer"`; same-origin, relative, and fragment links stay in the current tab. These review-only surfaces support light and dark mode, reduced motion, and the comments panel without changing the source Markdown. Only an explicit direct-local `--editable` save writes source.

The durable Markdown fixtures cover minimal prose, long documents, front-matter edge cases, heading hierarchy, ruler density, Mermaid, and folder-style wiki references:

```bash
tunelito ./examples/markdown/frontmatter-flat.md --no-tunnel --open
tunelito ./examples/markdown/heading-ladder.md --no-tunnel --open
tunelito ./examples/markdown-vault --no-tunnel --open
```

```bash
tunelito ./notes.md --markdown-css ./review.css
```

Serve a folder of HTML and Markdown files:

```bash
tunelito ./site
```

```bash
tunelito ./page.html --no-tunnel --open
```

```bash
tunelito doctor ./page.html --json
```

```bash
tunelito ./page.html --port 4400
```

Choose the comments file:

```bash
tunelito ./page.html --comments ./notes/review.md
```

Inspect the comments inbox as JSON for an agent or diagnostic tool:

```bash
tunelito comments inspect ./site --json
tunelito comments inspect ./site --comments ./notes/review.md --json
tunelito comments inspect ./site.comments.md --agent-state ./site/.tunelito/agent/state.json --json
tunelito comments inspect ./site.comments.md --json
```

Seed the local owner display name:

```bash
tunelito ./page.html --owner "Chekos"
```

Run an ephemeral in-meeting session:

```bash
tunelito ./page.html --ephemeral
```

Run Codex against review comments:

```bash
tunelito ./site --agent codex
```

Use the current agent session instead of spawning a child agent:

```bash
tunelito ./site --agent-session --owner "Chekos" --agent-policy owner-or-mention --agent-trigger "@agent"
```

The same process serves the room, watches comments, claims actionable feedback, prints a prompt for the current agent, and shows browser-visible status on each comment card. Record the current agent's result with the claim id from the printed command:

```bash
tunelito inbox record ./site --id c_... --claim claim_... --status resolved --summary "Updated hero copy." --file index.html
```

If a claim was taken by another foreground/background claimer in the same workspace, inspect it with `tunelito inbox status ./site` and record with `--claim auto` when you intentionally want to resolve the currently owning claim.

Print the same comment work tracker in the terminal:

```bash
tunelito inbox status ./site
```

Inspect or recover the served session from a second shell:

```bash
tunelito session status ./site
tunelito session status ./site --json
tunelito session status ./site --redact
```

The command verifies the listener's session identity, reports `running`, `degraded`, `stale`, or `stopped`, and includes local/public URLs, persistence, agent work, process, tunnel, viewer, and recovery details.

Wait for the reviewer to click `Done Reviewing` in the browser panel:

```bash
tunelito review watch --url "http://127.0.0.1:4317/?tunelito_key=..." --json --timeout 600
```

The handoff event is in-memory and retained only while the server is running. `review watch` replays retained events after sequence `0` by default; pass `--after latest` to wait only for a future click.

Start the MCP stdio adapter for MCP-capable agents:

```bash
tunelito mcp
```

The MCP server exposes comments index, pending feedback, claim, watch, record, and status tools. It does not start a review server, tunnel, browser, or local agent worker.

Print guided no-write agent setup instructions:

```bash
tunelito skill setup
```

Preview and install the bundled skill:

```bash
tunelito skill install --agent codex --scope user --dry-run
tunelito skill install --agent claude --scope project
```

Allow broad comments to continue for up to five passes:

```bash
tunelito ./site --agent codex --agent-max-passes 5
```

Run Claude Code against review comments:

```bash
tunelito ./site --agent claude
```

Use another local CLI:

```bash
tunelito ./site --agent-command "openclaw run --stdin"
```

Append host instructions to the worker prompt:

```bash
tunelito ./site --agent codex --agent-instructions "Use terse, production-ready copy."
```

Require an explicit marker for stricter sessions:

```bash
tunelito ./site --agent codex --agent-trigger "@agent"
```

Handle owner-authored or owner-approved comments automatically and visitor comments only when tagged:

```bash
tunelito ./site --owner "Chekos" --agent codex --agent-policy owner-or-mention --agent-trigger "@agent"
```
